# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A documentation portal (not the APM application itself) for a future Application Portfolio Management system for an IT Architecture team. It contains the system's architecture modeled in ArchiMate 3.2 as PlantUML code, published as a static Astro/Starlight site. All content and UI are in Spanish.

## Commands

All npm commands run from `website/` (Node.js ≥ 22.12, CI uses 24):

```sh
cd website
npm ci
npm run dev              # prepares PDFs, then astro dev
npm run build            # prepares PDFs, then astro build (output: website/dist)
npm run preview
npm test                 # node --test scripts/*.test.mjs
node --test scripts/prepare-pdfs.test.mjs   # single test file
npm run diagrams         # regenerate SVG/PNG + manifest.json (needs Java 17+ and plantuml.jar)
npm run diagrams:check   # verify manifest hashes match .puml sources (no Java needed)
```

`render-diagrams.mjs` finds the jar via `PLANTUML_JAR`, else `/tmp/opencode/plantuml/plantuml.jar`, `~/.local/share/plantuml/plantuml.jar`, or `~/.cache/apm/plantuml.jar`; Java via `JAVA_HOME`, a `jdk-*`/`jre*` folder in those cache dirs, or `PATH`. Use the PlantUML version pinned in `.github/workflows/docs.yml` (`PLANTUML_VERSION`).

## Architecture

- **Content lives outside the site.** `website/src/content.config.ts` loads the Starlight `docs` collection from `../docs` (`**/[^_]*.{md,mdx}`), so Markdown in `docs/` becomes pages. Files prefixed with `_` are excluded. The sidebar is hand-maintained in `website/astro.config.mjs` (only `guias/` is autogenerated), so new architecture pages must be added there. The same file injects an inline lightbox script for content images.
- **PDF and presentation pipeline.** `website/scripts/prepare-pdfs.mjs` and `website/scripts/prepare-presentations.mjs` run before `dev`/`build` and share `website/scripts/publish-files.mjs`: they copy every `.pdf` / `.pptx` under `docs/` (skipping hidden entries and symlinks) to `website/public/documentos/` / `website/public/presentaciones/` and write `website/src/generated/pdfs.json` / `presentaciones.json`, rendered by `website/src/pages/documentos.astro` / `presentaciones.astro`. Presentations embed the Office Online viewer, which only works on the public production domain (not localhost or protected previews). All outputs are generated and gitignored. Restart the dev server after changing these files.
- **Diagrams as code.** `docs/arquitectura/diagramas/*.puml` are the source of truth. Committed artifacts are the `.puml`, the generated `.svg` (referenced from Markdown as `./diagramas/<name>.svg`), and `manifest.json`; `.png` files are local-only (gitignored). CI checks SHA-256 hashes of `.puml` sources in `manifest.json` rather than SVG bytes, because PlantUML output varies with system fonts. Editing a `.puml` without running `npm run diagrams` fails CI.
- **CI** (`.github/workflows/docs.yml`): job `build` runs `npm test` + `npm run build`; job `render-diagrams` runs `diagrams:check` and then compiles all `.puml` with the pinned PlantUML to catch syntax errors.
- **Deployment** is via Vercel's Git integration with `website` as Root Directory and "include source files outside Root Directory" enabled (needed to read `docs/`). No remote/Vercel project is configured yet.

## Constraints

- Everything under `docs/` is public once deployed; keep internal documents out of it.
- Do not edit or commit `website/public/documentos/`, `website/public/presentaciones/` or `website/src/generated/`.
